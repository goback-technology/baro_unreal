## 목적

상명대 팀에서는 언리얼 기반 주차장 시뮬레이터의 원본 에셋과 레벨을 만들고, 저희는 그 에셋을 활용해 웹/AI 제어와 추가 산출물을 붙이는 입장입니다.

이번 문서는 상명대 팀의 작업 방향을 제한하려는 것이 아니라, 저희가 후속 작업에서 에셋을 바로 활용하기 쉽도록 정리해 주시면 좋은 내용을 부탁드리기 위한 것입니다. 핵심은 기능 구현보다 주차장 환경, 차량, 카메라 구도, 조명, 머티리얼, 레벨 구성, 불필요한 자산 정리입니다.

## 차이에서 보이는 정리 포인트

원본 프로젝트에는 실제 주차장 에셋, 생성용 플러그인 산출물, 마켓플레이스 샘플, UI/입력 템플릿, 패키징/캐시 흔적이 함께 섞여 있습니다. 저희가 후속 작업에서 가장 많이 시간을 쓰는 부분은 “무엇이 최종 에셋이고 무엇이 작업 과정의 흔적인지”를 다시 판단하는 일입니다.

그래서 아래 항목들이 구분되어 있으면 좋겠습니다.

1. 후속 조립에 사용할 수 있는 완성도 높은 주차장 에셋 묶음
2. 실험용/샘플용/중간 작업용 자산
3. 실제 주차장 구성에 필요한 필수 에셋
4. 다운로드 원본이나 마켓플레이스 샘플 에셋
5. 작업 중 사용했지만 최종 실행에는 필요 없는 플러그인
6. 테스트 UI, 입력, 캐릭터, 프로토타이핑 자산
7. CCTV 위치와 시야를 확인하기 위한 카메라 가이드

## 상명대 팀에 부탁드릴 사항

1. 후속 조립에 쓸 에셋과 작업 흔적을 구분해 주세요.
   - 저희 쪽에서는 별도 포털식 시뮬레이터 레벨을 다시 구성할 예정이라, 특정 대표 레벨을 정해 주실 필요는 없습니다.
   - 대신 완성도가 높은 주차장 구성 요소와 작업 중/실험용/샘플용 자산이 구분되어 있으면 좋겠습니다.
   - 레벨 파일도 최종 참고용, 작업 중, 샘플용 정도로 폴더나 이름 규칙이 나뉘어 있으면 후속 작업에서 혼동을 줄일 수 있습니다.

2. 불필요한 UI/입력/템플릿 자산을 분리해 주세요.
   - UMG 위젯, 미니맵, 테스트 HUD, 입력 액션, ThirdPerson 템플릿, 프로토타이핑 자산은 후속 작업에서 혼동되기 쉽습니다.
   - 바로 삭제하기 애매한 항목은 별도 폴더나 목록으로 “미사용 후보”라고 표시해 주시면 됩니다.

3. CCTV 카메라 구도와 차량/번호판 기준을 공유해 주세요.
   - 주차장 구조에 맞춰 카메라가 설치될 위치, 높이, 방향, 시야를 잡아 주세요.
   - 작업 중에는 언리얼 기본 카메라 액터나 가이드 액터로 화면 구도를 확인해도 됩니다.
   - 차량 모델과 번호판이 CCTV 구도에서 잘 보이는 배치 기준을 함께 맞추고 싶습니다.
   - 가능하다면 이후 차량 액터로 구성하기 쉽도록 휠이 분리된 구조면 좋겠습니다.
   - 번호판 텍스트/머티리얼/메시 구조가 정리되어 있으면 후속 인식 실험에 도움이 됩니다.
   - 실제 제어/스트리밍 연결은 저희가 후속 작업에서 맞추겠습니다.

4. 플러그인 의존성을 구분해 주세요.
   - 작업 과정에서 사용한 플러그인과 최종 실행에 필요한 플러그인을 구분해 주시면 좋겠습니다.
   - 생성용 플러그인을 사용한 경우, 가능하면 결과물을 베이크하거나 일반 에셋 형태로 넘겨 주세요.
   - 최종 프로젝트에서 꼭 필요한 플러그인은 목록으로 남겨 주세요.

## 에셋 작업 기준

- 레벨
  - 특정 대표 레벨을 정하기보다, 후속 조립에 참고할 수 있는 레벨과 실험/샘플 레벨이 구분되어 있으면 좋겠습니다.
  - 참고용 레벨에는 불필요한 테스트 액터, 샘플 UI, 디버그 오브젝트가 보이지 않으면 좋겠습니다.

- 폴더
  - 후속 조립에 사용할 에셋과 다운로드 원본/샘플/임시 에셋이 구분되어 있으면 좋겠습니다.
  - 중복 에셋팩이나 같은 목적의 머티리얼/텍스처는 어느 쪽을 기준으로 삼아야 하는지 표시해 주세요.

- 카메라
  - CCTV 설치 후보 위치를 언리얼 기본 카메라 액터나 가이드 액터로 남겨 주세요.
  - 카메라 이름은 사람이 이해하기 쉬운 이름이면 좋겠습니다. 예: `CCTV_Guide_01`, `CCTV_Guide_02`.
  - 각 카메라 시야에서 번호판, 차량, 주차면, 진입/출입 동선이 확인 가능하면 좋겠습니다.

- 주차면
  - 주차면 위치, 차선, 스토퍼, 장애인 구역, 진입/출입 동선이 카메라에서 식별 가능하게 정리되어 있으면 좋겠습니다.
  - 주차면 번호나 구역 구분이 있다면 이름이나 배치 규칙을 유지해 주세요.
  - 주차면 블루프린트는 가능하면 유지해 주세요.

- 차량/번호판
  - 차량 모델과 번호판은 CCTV 구도에서 너무 작거나 가려지지 않게 배치 기준을 잡아 주세요.
  - 번호판 인식 실험을 위해 주요 CCTV 구도에서 번호판이 식별 가능한 밝기와 크기로 보이면 좋겠습니다.
  - 가능하다면 차량 액터로 구성하기 쉽도록 휠을 분리해 주세요.

- 조명/머티리얼
  - 주간/야간 또는 주요 조명 조건에서 번호판과 차량이 과도하게 타거나 너무 어둡지 않게 맞춰 주세요.
  - 누락 머티리얼, 깨진 텍스처, 비정상 스케일 메시가 있으면 정리 부탁드립니다.

## 요청사항 정리

아래처럼 정리되어 있으면 저희가 후속 작업에서 에셋을 훨씬 수월하게 활용할 수 있습니다.

1. 후속 조립에 쓸 수 있는 주차장 에셋 묶음이 구분된 상태
2. 실험용/샘플용/중간 작업용 자산이 분리된 상태
3. 불필요한 UI, 입력, 캐릭터, 프로토타이핑 자산이 정리 또는 분리된 상태
4. CCTV 가이드 카메라에서 주차면, 차량, 번호판, 진입/출입 동선을 확인할 수 있는 상태
5. 차량, 번호판, 주차면 에셋이 후속 액터화와 인식 실험에 쓰기 쉬운 상태
6. 작업에 사용한 생성용 플러그인과 최종 실행에 필요한 플러그인이 구분된 상태
7. 캐시, 임시 빌드, 패키징 산출물이 원본 에셋 인계 범위와 구분된 상태
